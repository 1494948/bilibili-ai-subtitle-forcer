# B站 AI 字幕强制开启器

> 强行让哔哩哔哩网页播放器**长出「AI 自动生成字幕」这个开关**，并且点开之后真的能用。

一个 Chrome / Edge 扩展（Manifest V3）。适用场景：你打开一个视频，播放器右下角**根本没有字幕按钮**，
或者有字幕按钮但里面**只有 UP 主上传的字幕、没有「中文（自动生成）」这一项** —— 这个扩展就是冲这个来的。

---

## 1. 它是怎么"强行"做到的

先说清楚原理，因为这套做法决定了它**什么时候有效、什么时候无效**。

B 站网页播放器的字幕语言列表，**完全由一条接口的响应决定**：

```
GET https://api.bilibili.com/x/player/v2?aid=<avid>&cid=<cid>
GET https://api.bilibili.com/x/player/wbi/v2?aid=<avid>&cid=<cid>
```

播放器只认响应里 `data.subtitle.subtitles[]` 这个数组，并据此渲染出
`.bpx-player-ctrl-subtitle-language-item[data-lan="ai-zh"]` 这一项。
**这个数组空了，字幕按钮就不会出现** —— 而它在两种情况下会空：

| 情况 | 原因 |
|---|---|
| 未登录 | 响应里 `need_login_subtitle: true`，`subtitle` 直接被清空 |
| 条目被锁 | 条目上 `is_lock: true`，或者 UI 因为策略不渲染出来 |

而与此同时，**存在一条不需要登录的字幕数据通道**：

```
GET https://api.bilibili.com/x/v2/dm/view?aid=<avid>&oid=<cid>&type=1
```

它返回的结构里同样有 `data.subtitle`，里面就有 AI 字幕：

```json
{
  "lan": "ai-zh",
  "lan_doc": "中文(自动生成)",
  "type": 1,
  "is_lock": false,
  "subtitle_url": "//aisubtitle.hdslb.com/bfs/ai_subtitle/prod/....?auth_key=..."
}
```

于是扩展做的是三件事：

1. **预取**：在页面刚加载时就调上面那条免登录通道，把字幕列表拿到手；
2. **注入**：在 `document_start` 阶段劫持页面的 `XMLHttpRequest` / `fetch`，
   等播放器请求 `x/player/v2` 时，把预取到的字幕**合并进响应体**，
   并顺手拆掉两道闸门 —— 顶层 `need_login_subtitle` 置 `false`、条目 `is_lock` 置 `false`；
3. **打开**：播放器拿到被改过的 JSON，自己就会渲染出「中文（自动生成）」，
   扩展再替你把这个选项点开。

**关键点：注入的是播放器自己的数据源，所以字幕是 B 站自己渲染和播放的** ——
不需要我们模拟 UI、也不需要伪造画面。这也是为什么它在全屏、画中画、倍速下都正常。

## 2. 安装

### 方式一：加载已解压的扩展（推荐，改代码后立刻生效）

1. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）
2. 右上角打开 **开发者模式**
3. 点 **加载已解压的扩展程序**，选中本目录（含 `manifest.json` 的那一层）
4. 打开任意 B 站视频页，右下角会出现一个小提示条告诉你状态

> 需要 Chrome 111 或更高版本（`content_scripts` 的 `world: "MAIN"` 从这一版起支持）。

### 方式二：用打包好的 zip

```bash
node tools/make-zip.js
```

产物在 `dist-extension-v1.0.0/BASFCaptions-v1.0.0.zip`。
解压后用方式一加载即可（Chrome 不接受直接拖 zip 进扩展页）。

## 3. 用起来是什么样

装好之后打开视频页：

- **正常情况下**，几秒内弹出绿色提示「AI 字幕已注入：中文（AI 自动生成）」，
  播放器底部字幕栏里会多出「中文（自动生成）」，并且**已经自动选中**。
- 如果没有自动打开，**点一下右下角那个提示条**，它会再试一次。
- 也可以点扩展图标，在面板里点「强制开启字幕」。

面板上能看到的实时状态：字幕轨有哪些、当前 `aid` / `cid`、注入是否成功、自建渲染层开了几条字幕。

## 4. 设置项

| 分组 | 项 | 说明 |
|---|---|---|
| 注入方式 | 强制注入字幕数据 | 关掉就退化成"什么都不做"，方便对照排查 |
| | 自动打开 AI 字幕 | 注入成功后自动把语言点开；关掉就只注入、由你自己点 |
| | 渲染方式 | **用 B 站原生** / **原生 + 自建层**（默认）/ **只用自建层** |
| 双语与语言 | 双语对照 | 同时加载两条轨，上下两行显示（**需要自建渲染层**） |
| | 主 / 副语言 | 中文优先 AI 中文；英文优先 AI 英文 |
| 字幕样式 | 字号 / 距底 / 描边 / 底衬 / 颜色 / 最大宽度 | 只作用于自建渲染层 |
| ASR 兜底 | 见下一节 | |

**为什么有两套渲染？**
B 站原生字幕渲染在播放器内部的 shadow DOM 里，**字号、颜色、描边、位置全都改不动**，
而且一次只能显示一条轨 —— 所以「双语对照」和「样式自定义」必须靠自建渲染层。
两套的取舍：

- 用原生：最省事，和站内体验完全一致，但不可定制
- 用自建层：能双语能改样式，但需要多下载一次字幕文件（几 KB），并且会**自动隐藏原生字幕**避免两层重叠

## 5. ASR 兜底（可选，默认关闭）

如果预取和注入都拿不到字幕，说明**这个视频服务端确实没有生成过 AI 字幕**。
这时候唯一的办法是自己识别音频。扩展的做法：

```
AudioContext 抓视频音轨 → MediaRecorder 分片 → 后台转发到你自己配的 ASR 接口
→ 拿回文本 + 时间戳 → 交给自建渲染层显示
```

配置方式：面板里填一个 **OpenAI 兼容**的语音转写地址（形如
`https://your-host/v1/audio/transcriptions`）、API Key、模型名，
然后点「**授权该接口域名**」—— 授权后请求由扩展后台发出，不受页面跨域限制。

**它不是自动跑的**。只有当你看到提示「这个视频没有 AI 字幕 —— 点这里现场识别」并点了它，才会开始。

已知限制（写在前面，省得你以为是 bug）：

1. **必须保持视频在播放、标签页在前台**，切走或暂停就会断片；
2. 如果视频源 CDN 没开放 CORS，`createMediaElementSource` 会拿到**纯静音** ——
   扩展会在几秒内检测到并明确报错，而不是空转；
3. 时间戳精度受分片长度限制（默认 20 秒一片，片内再按标点均分），
   接**带 `segments` 时间轴**的服务会准得多；
4. 长视频会产生很多次请求，注意你自己接口的**费用和限流**。

## 6. 已知限制与尚未验证的部分

**已经验证过的**（`node tools/selftest.js`，135 项全通过）：

- manifest 合法性：MV3 必填项、版本格式、描述长度、引用的文件是否都存在、
  `matches` 没有写成全站、`optional_host_permissions` 与 `host_permissions` 不重复
- 全部 JS 的语法（用 `new Function` 解析，不起子进程）
- `popup.html` 的 `id` 与 `popup.js` 引用的是否对得上、本地资源是否存在
- **注入核心 `mergeSubtitle` 的六种情形**：无 `subtitle` 节点时新建、
  已有普通字幕时不覆盖只追加、重复注入幂等、接口报错时不注入、
  空数据不注入、关掉 forceUnlock 时不动闸门
- 语言选择、字幕 JSON 解析、时间轴二分查找（含切点边界）、SRT 输出、设置模型的越界钳制

**尚未验证的（请知悉）**：

- **没有在真实 B 站页面上做过端到端手测。** 本仓库的验证全部是离线的。
  装到浏览器后请按第 3 节核对一遍。
- **Chrome 对这份 manifest 的实际接受度没有实机验证过**，尤其是
  `optional_host_permissions` 与 `content_scripts.world` 的兼容表现。
- **B 站接口可能随时变。** 一旦 `x/v2/dm/view` 不再返回字幕，或者播放器改用别的数据源，
  注入就会失效 —— 届时需要更新 `lib/bili-api.js` 里的 `SUBTITLE_ENDPOINTS`。
- 播放器 DOM 选择器（`.bpx-player-ctrl-subtitle` 等）是同名类，B 站改版可能失效，
  相关选择器集中在 `src/content.js` 顶部的 `SEL` 对象里，便于替换。

## 7. 隐私与边界

- **不发送任何数据到第三方。** 所有请求都直连 B 站自己的域名。
  只有你自己显式配置并启动 ASR 时，音频分片才会发往**你自己填的地址**。
- **不绕过付费内容。** 本扩展只处理"字幕列表被前端隐藏"这一类问题，
  不涉及充电专属视频、大会员画质、付费课程的权限。遇到这些，该看不到还是看不到。
- API Key 存在 `chrome.storage.local`（本机），不使用 `sync`，不会被同步到云端。
- 扩展只申请了 `storage` 一项权限；对 B 站域名之外的可选权限要你在面板里手动点授权才会生效。

## 8. 常见问题

**装了没反应？**
先看右下角有没有提示条。没有的话打开扩展面板看状态：
显示"当前标签页不是 B 站视频页"说明这个标签页没被匹配（本扩展只匹配
`/video/`、`/bangumi/play/`、`/list/`、`/medialist/play/`、`/watchlater/`、`/cheese/play/`）。

**提示"正在等待播放器请求…"但一直不注入？**
刷新一次页面（`Ctrl+Shift+R` 强制无缓存刷新）。注入逻辑必须在 `document_start` 就跑起来，
如果扩展是在页面已经加载完后才被启用，这一次就赶不上了。

**注入成功了，但没自动点开字幕？**
点一下右下角提示条手动触发。若还是不行，说明播放器的语言列表结构变了，
需要更新 `src/content.js` 里的 `SEL` 选择器。

**字幕位置和弹幕打架？**
面板里把「距底」调高一点，或者直接用原生渲染模式。

## 9. 开发

```bash
node tools/selftest.js      # 离线自检，135 项；失败退出码 1
node tools/make-zip.js      # 打包，产物在 dist-extension-v<版本>/
node tools/make-zip.js --out <目录>   # 指定输出目录
python tools/make-icons.py  # 重新生成图标（纯标准库，不需要 Pillow）
```

代码结构：

```
manifest.json
lib/
  bili-api.js    ← 全部纯逻辑：接口地址构造、响应提取、注入合并、语言选择、字幕解析
  settings.js    ← 设置模型：默认值 + 越界钳制
src/
  hook.js        ← MAIN world。劫持 XHR/fetch 做注入。★ 核心在这
  content.js     ← 隔离世界。编排：收事件、点开字幕、拉字幕内容、转发 popup 指令
  overlay.js     ← 自建字幕渲染层（双语 + 样式）
  asr.js         ← 可选 ASR 兜底
  background.js  ← service worker：ASR 转发、统计、默认设置
  popup.*        ← 设置面板
tools/
  selftest.js    ← 离线自检
  make-zip.js    ← 零依赖 ZIP 打包器
  make-icons.py  ← 零依赖 PNG 图标生成
```

改代码时的两个"必须"：

1. `lib/*.js` 都写成**双出口**（既能被 Node `require`，又挂到 `globalThis`），
   这样纯逻辑才能被自检覆盖。新增纯函数请一并加测试。
2. 注入相关代码放 `src/hook.js`（MAIN world），**不能**放 `content.js` ——
   隔离世界改不到页面自己的 `XMLHttpRequest` 和响应对象。
